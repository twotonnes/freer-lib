#+TITLE: Queue-based bind: detailed design

* Summary
Implemented; the code and its tests match this document. The only open item is the Cost re-measure. The release step is done (commit 8f450d8).

A waiting computation (=impure=) keeps its pending continuations in a queue, a third field
of the structure, instead of wrapping its continuation again on every bind. Bind appends one
function to the queue; resuming pops functions until the next effect. The library is pure
throughout, and the handler interface (=run=, the description and the continuation) is unchanged.

* Design
** Data structures
#+begin_src racket
(struct pure (value) #:transparent)                 ; unchanged
(struct impure (description k queue) #:transparent) ; queue is new
(struct leaf (f))                                   ; one pending continuation (-> Any Free)
(struct node (left right))                          ; two non-empty queues
#+end_src

- =pure= is unchanged.
- =impure= has three fields. =description= is the effect description. =k= is a procedure
  (-> Any Free) that resumes the queue: it is built by =make-impure= as a closure over the
  queue, so a handler calls it exactly as today. =queue= holds the pending continuations.
- The library builds waiting computations only through =make-impure=, so =k= always resumes
  its own =queue=, and =queue= is never empty. The struct is exported by name and its
  constructor is public, so a user could build one with a queue of their own; the
  documentation directs users to =perform=, =return= and >>= instead, and this is not
  guarded.
- =leaf= and =node= are internal. They are not exported and are not transparent, so
  =equal?= on them is =eq?=, as it is today for the continuation procedures.
- A queue is a tree of =leaf= and =node=, read left to right. The empty queue is =#f=; it
  appears only as the remainder after the last function is popped, never inside a =node=.

** Procedures
Types follow the code-writer's convention (see =.claude/agents/code-writer.md=). The name
>>= is the exported name; it is the same procedure as =bind= (the code exports >>=, and =bind= is
an internal name for it; a test checks =eq?=). Procedures
not listed are unchanged: =free?=, =do-m=, =sequence=, =map-m=. =bind= is not exported; =>>== is.

- =perform= realises requirement 1 and 2. It builds a waiting computation whose only pending
  continuation is =return=.
  #+begin_src racket
  ;; Type: (-> Any Impure)
  (define (perform desc) (make-impure desc (leaf return)))
  #+end_src
- =make-impure= builds the waiting structure. It is the only place =impure= is constructed in
  the library.
  #+begin_src racket
  ;; Type: (-> Any Queue Impure)
  (define (make-impure desc queue)
    (impure desc (lambda (x) (resume queue x)) queue))
  #+end_src
- =bind= realises requirements 3 and 7. A pure value is
  passed to the function. A waiting computation gets the function appended to its queue, at
  O(1) cost.
  #+begin_src racket
  ;; Type: (-> Free (-> Any Free) Free)
  (define (bind m f)
    (match m
      [(pure v) (f v)]
      [(impure d _ q) (make-impure d (q-append q (leaf f)))]))
  #+end_src
- =resume= realises requirements 2, 4 and 7. It pops the first function, applies it to the value,
  and continues with the rest of the queue while the result is pure. It stops at the first
  waiting result and joins that result's queue to the rest of the queue.
  #+begin_src racket
  ;; Type: (-> Queue Any Free)
  (define (resume q x)
    (let-values ([(f rest) (q-pop q)])
      (define m (f x))
      (cond [(not rest) m]
            [else (match m
                    [(pure v) (resume rest v)]
                    [(impure d _ q2) (make-impure d (q-append q2 rest))])])))
  #+end_src
  The pure path is a tail call, so a long run of pure results does not grow the stack.
- =q-append= joins two queues in O(1). One side may be empty.
  #+begin_src racket
  ;; Type: (-> (U Queue #f) (U Queue #f) (U Queue #f))
  #+end_src
- =q-pop= returns the first function and the remaining queue. When the left child of a =node=
  is itself a =node=, it rotates the tree to the right (=(node (node a b) r)= becomes
  =(node a (node b r))=) until the left child is a =leaf=. Each rotation step is one
  constant-time step.
  #+begin_src racket
  ;; Type: (-> Queue (Values (-> Any Free) (U Queue #f)))
  #+end_src
  Called only on a non-empty queue.
- =run= realises requirement 1 and 3. Its code changes only in its match of the waiting
  structure, which now has three fields. A pure result is returned, and a waiting one is passed
  to the handler as its description and its =k=.
  #+begin_src racket
  ;; Type: (-> Free (-> Any (-> Any Free) Free) Any)
  #+end_src
- =catch= in =try-catch.rkt= realises requirement 5. Its failure clause matches the three-field
  structure with one more wildcard. Its waiting clause must not call the constructor with two
  arguments, so it is rewritten to bind a fresh =perform= to the function that catches the rest.
  This gives the same observable result:
  #+begin_src racket
  ;; Type: (-> Free Free)
  (define (catch computation)
      (match computation
          [(pure value) (return value)]
          [(impure (failure-effect fallback) _ _) fallback]
          [(impure eff k _) (>>= (perform eff) (lambda (value) (catch (k value))))]))
  #+end_src

** Why this shape
- The old =bind= wraps the continuation again on every bind, so an effect that is under n
  nested binds passes through n wrappers. The queue appends instead, and a pop costs the
  same whatever the number of pending binds.
- =k= stays a one-argument procedure stored in the same field, so the handler contract
  (=run= passes the description and the continuation) does not change.
- The queue is immutable and =k= closes over it. A continuation resumed twice therefore
  gives the same results both times (requirement 2).
- =perform= no longer stores =return= itself as =k=. Any code that tests =(eq? (impure-k m) return)=
  would see a difference. The spec does not require it, and no code in the repository does so.
- =(equal? (perform d) (perform d))= is now =#f=; it was =#t= before. Each =perform= builds a
  fresh continuation closure and =leaf= is opaque. The spec's requirements concern run results
  and effect traces, not =equal?= on waiting structures, so this is a deliberate, accepted
  change. It is recorded in the Migration subsection of the 1.0.0 =CHANGELOG.md= entry (release
  step). Tests do not compare waiting computations with =equal?=.

** Effects and the pure/impure boundary
- The feature has no effects and no outside state. All procedures above are pure, as
  [[file:../../design/decisions/0001-no-contracts.org][decision 0001]] and =.claude/rules/pure-code.md= require.
- Continuations supplied by the user, and handlers, run inside =resume= and =run=. An error
  they raise propagates to the caller, as today (requirement 5). The library holds no state
  that outlives a call, so a later =run= is unaffected.
- Inputs that are not free values fail the =match= in =bind= and =run=, as today. That
  behaviour is kept; the type comments state the precondition.

** Cost
Historical measurements, as measured with the scratch prototype (not in the repository) on the same machine as the old code, before the change. They have not been re-measured on the implemented code (open):

| Case | Old | New prototype |
|------+-----+---------------|
| Recursive bracket, depth 1000 / 2000 / 4000 / 8000 | 9 / 38 / 167 / 755 ms | 0 / 0 / 1 / 1 ms |
| Recursive bracket, depth 16000 | not run | 3 ms |
| 100 000 left-nested binds on one effect | 6 ms | 9 ms |
| 100 000 right-nested binds with effects | 3 ms | 4 ms |
| 100 resumes of one continuation, 20 000 left-nested binds | 23 ms | 54 ms |

In a single resumption, the first pop pays one rotation of the left spine of the queue, and
every later pop is constant time, so a queue that is resumed once costs time linear in its
size. Repeated resumption of the same continuation pays that rotation again, because the
rotated tree is not stored. Today's code pays the full wrapper chain on every resumption.

This repeated-resumption case is the accepted limit (54 ms against 23 ms for 100 resumes at
depth 20 000). The spec states it under Out of scope. The timing check below (requirement 7)
applies to single resumption only.

** Deliberate documentation change: predicate and accessors
The spec requires that the reference documentation no longer documents accessors that are not
exported (requirement 6). The struct name is exported with its constructor. The predicate and
the accessors are not, so the documentation must not name them. The change is made. Nothing in =scribblings/= may name =impure?=,
=impure-k= or =impure-description= afterwards.

The return types and argument types that use =impure?= become =free?=, which is exported and
has the same test (pure or waiting). The examples that call the two-field constructor are
rebuilt with the operations.
