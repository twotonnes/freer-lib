3 Standard Effects🔗

 (require freer-lib/effects/main) package: freer-lib

While the core library allows you to define any effect you wish, this module provides a set of common, pre-defined effects for everyday tasks like file I/O, HTTP requests, system commands, logging, and random numbers. The freer-lib/effects/main module re-exports every effect module described in this section, and is itself re-exported by freer-lib.

Some of these effects come with companion default handlers: plain procedures that actually perform the requested operation (for example execute-command, perform-http-request, write-log, do-rnd and the do-read-file family). No handler is installed automatically; you always write the handler passed to run yourself, and decide per effect whether to call a default handler or to mock the effect, e.g. for testing.

3.1 Understanding Basic Effects🔗

To understand how these standard effects work, consider the simplest one: the Identity effect.

 (require freer-lib/effects/id-effect) package: freer-lib

struct

(struct id-effect (value)
    #:transparent)
  value : any/c
A descriptor that simply holds a value.

procedure

(id v) → free?

  v : any/c
Constructs an effect that wraps v.

When you use id, you are effectively pausing the computation to hand a value to the handler, which is expected to hand it right back.

Examples:
> (define computation
    (do-m [x <- (id 10)]
        [y <- (id 20)]
        (return (+ x y))))
; A handler that simply unwraps the ID and returns the value
> (run computation
       (lambda (eff k)
          (match eff
            [(id-effect v) (k v)])))

30

3.2 System Commands🔗

 (require freer-lib/effects/cmd-effect) package: freer-lib

This module provides effects for executing shell commands and capturing their output.

struct

(struct cmd-effect (value)
    #:transparent)
  value : any/c
An effect descriptor for running a system command. value is the command to run; the default handler execute-command requires it to be a string.

struct

(struct cmd-result (out err exit-code)
    #:transparent)
  out : string?
  err : string?
  exit-code : byte?
The structure returned by execute-command after a command completes.

  • out: Standard output captured as a string.

  • err: Standard error captured as a string.

  • exit-code: The exit code of the process.

procedure

(cmd value) → free?

  value : any/c
Creates an effect that requests the execution of the command value.

Example:
> (define (check-status)
    (do-m [res <- (cmd "git status")]
          (if (zero? (cmd-result-exit-code res))
              (return (cmd-result-out res))
              (return "Git check failed"))))

procedure

(execute-command value) → cmd-result?

  value : string?
The default handler for cmd-effect. It runs value with PowerShell, by invoking powershell.exe -Command value, waits for the process to finish and returns a cmd-result containing the output, error output, and exit code. A non-zero exit code is not treated as an error.

powershell.exe must be available in the PATH. If it cannot be found, or if anything else goes wrong while running the process, an exception is raised whose message includes the command.

A handler that uses execute-command looks like this:

(run (check-status)
     (lambda (eff k)
       (match eff
         [(cmd-effect c) (k (execute-command c))])))

For testing, execute-command can be replaced by a mock:

Example:
> (run (check-status)
       (lambda (eff k)
         (match eff
           [(cmd-effect c) (k (cmd-result "nothing to commit\n" "" 0))])))

"nothing to commit\n"

3.3 HTTP Requests🔗

 (require freer-lib/effects/http-effect) package: freer-lib

This module provides effects for performing HTTP network requests.

struct

(struct http-effect (url method headers data)
    #:transparent)
  url : url?
  method : (or/c 'GET 'POST 'PUT 'PATCH 'DELETE)
  headers : (listof string?)
  data : (or/c #f bytes? string?)
The descriptor containing all necessary information to perform a request.

  • url: The parsed request URL (see string->url).

  • method: The HTTP method.

  • headers: Request headers, each formatted as "Name: value".

  • data: The request body, or #f for 'GET and 'DELETE requests.

procedure

(http-get url headers) → free?

  url : string?
  headers : (listof string?)
Creates a GET request effect for url. The url string is parsed with string->url when the effect is created.

Example:
> (define (fetch-home)
    (do-m [(list status headers body) <- (http-get "https://racket-lang.org" '())]
        (return (format "Status: ~a, Body length: ~a"
                        status
                        (string-length body)))))

procedure

(http-post url headers data) → free?

  url : string?
  headers : (listof string?)
  data : (or/c bytes? string?)
Creates a POST request effect for url with data as the request body.

procedure

(http-put url headers data) → free?

  url : string?
  headers : (listof string?)
  data : (or/c bytes? string?)
Creates a PUT request effect for url with data as the request body.

procedure

(http-patch url headers data) → free?

  url : string?
  headers : (listof string?)
  data : (or/c bytes? string?)
Creates a PATCH request effect for url with data as the request body.

procedure

(http-delete url headers) → free?

  url : string?
  headers : (listof string?)
Creates a DELETE request effect for url.

procedure

(perform-http-request req)

 → (list/c number? (listof string?) string?)
  req : http-effect?
The default handler for http-effect, implemented with http-sendrecv/url from Racket’s net/url library.

It returns a list containing:

'(status-code headers-list body-string)

  • status-code: Exact integer (e.g., 200, 404).

  • headers-list: A list of strings representing response headers.

  • body-string: The response body, decoded as a string.

Non-2xx status codes are not treated as errors. If an error occurs while performing the request (e.g., a network error or connection timeout), an exception is raised whose message includes the request.

A handler that uses perform-http-request looks like this:

(run (fetch-home)
     (lambda (eff k)
       (match eff
         [(? http-effect?) (k (perform-http-request eff))])))

Examples:
; Mocking the HTTP handler lets tests run without network access.
> (run (fetch-home)
       (lambda (eff k)
         (match eff
           [(http-effect url method headers data)
            ; Return a fake 200 OK response
            (k (list 200 '("Content-Type: text/html") "<html>Mock Body</html>"))])))

"Status: 200, Body length: 22"

3.4 Abort Effect🔗

 (require freer-lib/effects/abort-effect)
  package: freer-lib

The abort effect allows computations to signal immediate termination without producing a value.

struct

(struct abort-effect ())

An effect descriptor that represents an abort signal. The struct has no fields and is opaque.

procedure

(abort) → free?

Creates an effect that signals termination of the current computation.

There is no default handler. A handler typically implements an abort by not calling the continuation and returning some final computation instead, which discards the rest of the computation.

Examples:
> (define (conditional-abort x)
    (do-m (if (negative? x)
              (abort)
              (return (void)))
          (return (abs x))))
> (define (handler eff k)
    (match eff
      [(? abort-effect?) (return 'aborted)]))
> (run (conditional-abort 5) handler)

5

> (run (conditional-abort -5) handler)

'aborted

The abort effect is useful for control flow when you need to exit a computation early without producing a normal return value.

3.5 Failure Effect🔗

 (require freer-lib/effects/failure-effect)
  package: freer-lib

The failure effect allows computations to signal failure with an error message. This is useful for error handling and control flow in effectful computations.

struct

(struct failure-effect (msg))

  msg : string?
A descriptor that represents a failure with an associated error message. The struct is opaque, so handlers should use failure-effect? and failure-effect-msg (or a struct pattern in match) to inspect it.

procedure

(failure msg) → free?

  msg : string?
Constructs an effect that signals failure with the given error message.

There is no default handler. A handler typically does not resume the continuation, so that the rest of the computation is skipped.

The failure effect can be used to propagate errors through a computation, for example when the result of a command execution or HTTP request is not what was expected.

Examples:
> (define (check-size x)
    (do-m [v <- (id x)]
          (if (< v 20)
              (failure "Value is too small")
              (return v))))
> (define (handler eff k)
    (match eff
      [(id-effect v) (k v)]
      [(failure-effect msg) (return (format "failed: ~a" msg))]))
> (run (check-size 10) handler)

"failed: Value is too small"

> (run (check-size 30) handler)

30

3.6 Logging🔗

 (require freer-lib/effects/log-effect) package: freer-lib

This module provides effects for logging messages at different severity levels.

struct

(struct log-effect (level message)
    #:transparent)
  level : symbol?
  message : string?
An effect descriptor for logging a message at a specified level.

  • level: A symbol indicating the log level. The constructors in this module produce 'DEBUG, 'INFO and 'ERROR.

  • message: The log message, already formatted.

procedure

(log-dbg message args ...) → free?

  message : string?
  args : any/c
Creates a logging effect that logs a message at the 'DEBUG level. When args are given, the message is produced by (apply format message args); otherwise message is used as is.

Example:
> (define (process-data)
    (do-m [_ <- (log-dbg "Starting data processing")]
        [result <- (return 42)]
        [_ <- (log-dbg "Processing complete with result: ~a" result)]
        (return result)))

procedure

(log-inf message args ...) → free?

  message : string?
  args : any/c
Creates a logging effect that logs a message at the 'INFO level. When args are given, the message is produced by (apply format message args); otherwise message is used as is.

Example:
> (define (startup)
    (do-m [_ <- (log-inf "Application started")]
        (return (void))))

procedure

(log-err message args ...) → free?

  message : string?
  args : any/c
Creates a logging effect that logs a message at the 'ERROR level. When args are given, the message is produced by (apply format message args); otherwise message is used as is.

Example:
> (define (handle-failure)
    (do-m [_ <- (log-err "Critical failure occurred")]
        (return (void))))

procedure

(write-log eff [display-proc]) → void?

  eff : log-effect?
  display-proc : (-> log-effect? void?) = default-log-display
The default handler for log-effect. Writes the log message in eff by calling display-proc on it. If display-proc raises an exception, it is re-raised as an error whose message describes the failure.

  • eff: The log effect to write.

  • display-proc: A procedure that displays the log message. The default (which is not exported) prints a line of the form [timestamp] level :: message, where timestamp is the current UTC time in ISO 8601 format. 'ERROR messages are written to (current-error-port), all other levels to (current-output-port), and the port is flushed afterwards.

Examples:
> (define (custom-display eff)
    (displayln (format "[~a] ~a" (log-effect-level eff) (log-effect-message eff))))
> (run (log-inf "Custom logging example")
       (lambda (eff k)
         (match eff
           [(log-effect level msg)
            (write-log eff custom-display)
            (k (void))])))

[INFO] Custom logging example

The log effect is typically used for observability and diagnostics. When logging is not wanted (e.g., in a testing environment), you can write a handler that ignores log messages or collects them for inspection.

Examples:
; A handler that collects log messages instead of printing them
> (define (run-collecting-logs computation)
    (define logs '())
    (define result
      (run computation
           (lambda (eff k)
             (match eff
               [(log-effect level msg)
                (set! logs (cons (list level msg) logs))
                (k (void))]))))
    (values result (reverse logs)))
> (run-collecting-logs (process-data))

42

'((DEBUG "Starting data processing")

  (DEBUG "Processing complete with result: 42"))

3.7 File System🔗

 (require freer-lib/effects/file-system-effect)
  package: freer-lib

This module provides effects for performing file system operations such as reading, writing, creating directories, and checking or deleting paths.

3.7.1 Structs🔗

struct

(struct read-file-effect (path)
    #:transparent)
  path : path-string?
An effect descriptor that represents a file read operation.

  • path: The path to the file to read.

struct

(struct write-file-effect (path bytes exists-flag)
    #:transparent)
  path : path-string?
  bytes : bytes?
  exists-flag : (or/c 'error 'append 'update 'replace 'truncate 'truncate/replace)
An effect descriptor that represents a file write operation.

  • path: The path to the file to write.

  • bytes: The bytes to write to the file.

  • exists-flag: Controls behavior if the file already exists, with the same meaning as the #:exists argument of open-output-file:

    • 'error: Raise an error if the file exists.

    • 'append: Append to the end of the existing file.

    • 'update: Open the existing file without truncating it and write from the start; raise an error if the file does not exist.

    • 'replace: Delete the existing file and create a new one.

    • 'truncate: Remove all existing data from the file and write to it.

    • 'truncate/replace: Like 'truncate, but fall back to 'replace if truncating fails.

struct

(struct create-folder-effect (path)
    #:transparent)
  path : path-string?
An effect descriptor that represents a folder creation operation.

  • path: The path to the folder to create. Parent directories are created if necessary.

struct

(struct check-path-effect (path)
    #:transparent)
  path : path-string?
An effect descriptor that represents a path type check operation.

  • path: The path to check.

struct

(struct delete-path-effect (path)
    #:transparent)
  path : path-string?
An effect descriptor that represents a path deletion operation.

  • path: The path to the file or directory to delete.

3.7.2 Procedures🔗

procedure

(read-file path) → free?

  path : path-string?
Creates an effect that reads the file at path and returns its contents as bytes.

Examples:
; Define a mock handler for testing
> (define (mock-fs-handler effect k)
    (match effect
      [(read-file-effect path)
       (k (string->bytes/utf-8 "config-data"))]
      [_ (error "unhandled effect")]))
; Use the effect in a computation
> (define (read-config-file)
    (do-m [content <- (read-file "config.txt")]
        (return (bytes->string/utf-8 content))))
; Run with mock handler
> (run (read-config-file) mock-fs-handler)

"config-data"

procedure

(write-file path bytes exists-flag) → free?

  path : path-string?
  bytes : bytes?
  exists-flag : (or/c 'error 'append 'update 'replace 'truncate 'truncate/replace)
Creates an effect that writes bytes to the file at path. The exists-flag parameter controls behavior if the file already exists.

Examples:
; Mock handler that confirms writes
> (define (write-handler effect k)
    (match effect
      [(write-file-effect path bytes flag)
       (k (void))]
      [_ (error "unhandled effect")]))
> (define (save-document content)
    (do-m [_ <- (write-file "document.txt"
                          (string->bytes/utf-8 content)
                          'truncate)]
        (return "Document saved!")))
> (run (save-document "Hello, world!") write-handler)

"Document saved!"

procedure

(create-folder path) → free?

  path : path-string?
Creates an effect that creates a folder at path. All necessary parent directories are created automatically.

Examples:
> (define (folder-handler effect k)
    (match effect
      [(create-folder-effect path)
       (k (void))]
      [_ (error "unhandled effect")]))
> (define (setup-workspace dir-name)
    (do-m [_ <- (create-folder (string-append "projects/" dir-name "/src"))]
        [_ <- (create-folder (string-append "projects/" dir-name "/tests"))]
        (return (string-append "Workspace '" dir-name "' created"))))
> (run (setup-workspace "my-project") folder-handler)

"Workspace 'my-project' created"

procedure

(check-path path) → free?

  path : path-string?
Creates an effect that checks the type of a path and returns a symbol indicating whether it is a file, directory, symbolic link, directory symbolic link, or does not exist.

Returns one of:

  • 'file: A regular file

  • 'directory: A directory

  • 'link: A symbolic link to a file

  • 'directory-link: A symbolic link to a directory

  • #f: The path does not exist

Examples:
> (define (check-handler effect k)
    (match effect
      [(check-path-effect "existing.txt") (k 'file)]
      [(check-path-effect "my-folder") (k 'directory)]
      [(check-path-effect _) (k #f)]
      [_ (error "unhandled effect")]))
> (define (handle-path path)
    (do-m [type <- (check-path path)]
        (match type
          ['file (return "It's a file")]
          ['directory (return "It's a directory")]
          [#f (return "Path does not exist")]
          [_ (return "It's a link")])))
> (run (handle-path "existing.txt") check-handler)

"It's a file"

> (run (handle-path "my-folder") check-handler)

"It's a directory"

> (run (handle-path "missing.txt") check-handler)

"Path does not exist"

procedure

(delete-path path) → free?

  path : path-string?
Creates an effect that deletes a file or directory at path. If the path is a directory, it and all its contents are recursively deleted. If the path does not exist, no error is raised.

Examples:
> (define (delete-handler effect k)
    (match effect
      [(delete-path-effect path)
       (k (void))]
      [_ (error "unhandled effect")]))
> (define (cleanup)
    (do-m [_ <- (delete-path "temp.txt")]
        [_ <- (delete-path "old-data")]
        (return "Cleanup complete")))
> (run (cleanup) delete-handler)

"Cleanup complete"

3.7.3 Default Handlers🔗

procedure

(do-read-file path) → bytes?

  path : path-string?
Default handler for read-file-effect. Reads the file at path and returns its contents as bytes. Raises an error that includes path if the file cannot be read.

procedure

(do-write-file path bytes exists-flag) → void?

  path : path-string?
  bytes : bytes?
  exists-flag : (or/c 'error 'append 'update 'replace 'truncate 'truncate/replace)
Default handler for write-file-effect. Writes bytes to path with the specified exists-flag. Raises an error if the file cannot be written.

procedure

(do-create-folder path) → void?

  path : path-string?
Default handler for create-folder-effect. Creates the folder at path and all necessary parent directories. Raises an error if the folder cannot be created.

procedure

(do-check-path path)

 → (or/c 'file 'directory 'link 'directory-link #f)
  path : path-string?
Default handler for check-path-effect. Returns a symbol indicating the type of the path (see file-or-directory-type), or #f if it does not exist.

procedure

(do-delete-path path) → void?

  path : path-string?
Default handler for delete-path-effect. Deletes the file or directory at path. If the path is a directory, all its contents are recursively deleted. Does not raise an error if the path does not exist.

3.7.4 Usage Example🔗

Examples:
; Example: Copy a file with path type checking
> (define (copy-handler effect k)
    (match effect
      [(check-path-effect "source.txt") (k 'file)]
      [(read-file-effect "source.txt")
       (k (string->bytes/utf-8 "file contents"))]
      [(write-file-effect path bytes flag) (k (void))]
      [_ (error "unhandled effect")]))
> (define (copy-file-if-exists src dst)
    (do-m [src-type <- (check-path src)]
        (if (eq? src-type 'file)
            (do-m [content <- (read-file src)]
                [_ <- (write-file dst content 'truncate)]
                (return "File copied successfully"))
            (return "Source file does not exist"))))
> (run (copy-file-if-exists "source.txt" "dest.txt") copy-handler)

"File copied successfully"

A handler that dispatches every file system effect to its default handler looks like this:

(define (fs-handler effect k)
  (match effect
    [(read-file-effect path) (k (do-read-file path))]
    [(write-file-effect path bytes flag) (k (do-write-file path bytes flag))]
    [(create-folder-effect path) (k (do-create-folder path))]
    [(check-path-effect path) (k (do-check-path path))]
    [(delete-path-effect path) (k (do-delete-path path))]))

Error Handling: File system operations can fail due to permission issues, missing files, or other I/O errors. The default handlers catch the Racket exceptions raised by the underlying operations and re-raise them as errors whose message includes the path that was being accessed. You can write custom handlers to implement retry logic, fallback behavior, or alternative error handling strategies.

3.8 Environment🔗

 (require freer-lib/effects/env-effect) package: freer-lib

This module provides an effect for reading a value from an environment, such as an environment variable or a configuration setting. What the environment is, and what keys it accepts, is decided entirely by the handler; there is no default handler.

The effect descriptor is defined as a record type with rebellion/type/record, so it is constructed with a keyword argument.

procedure

(read-env-effect #:kw kw) → read-env-effect?

  kw : any/c
Constructs an effect descriptor that requests the value associated with the key kw.

procedure

(read-env-effect? v) → boolean?

  v : any/c
Returns #t if v is a read-env-effect, #f otherwise.

procedure

(read-env-effect-kw eff) → any/c

  eff : read-env-effect?
Returns the key requested by eff.

procedure

(read-env kw) → free?

  kw : any/c
Creates an effect that requests the value associated with the key kw.

Examples:
> (define (greeting)
    (do-m [user <- (read-env "USER")]
          (return (format "Hello, ~a!" user))))
; A handler that reads from a fixed table instead of the real environment
> (define (env-handler eff k)
    (match eff
      [(? read-env-effect?)
       (k (hash-ref (hash "USER" "alice") (read-env-effect-kw eff) #f))]))
> (run (greeting) env-handler)

"Hello, alice!"

3.9 Random Numbers🔗

 (require freer-lib/effects/rnd-effect) package: freer-lib

This module provides an effect for generating random integers. Keeping randomness behind an effect makes computations that use it deterministic under test.

struct

(struct rnd-effect (min max)
    #:transparent)
  min : exact-integer?
  max : exact-integer?
An effect descriptor that requests a random integer in the range from min (inclusive) to max (exclusive).

procedure

(rnd min max) → free?

  min : exact-integer?
  max : exact-integer?
Creates an effect that requests a random integer n such that (<= min n) and (< n max).

; A deterministic handler for testing that always returns the minimum
> (run roll-two-dice
       (lambda (eff k)

3.10 Try-Catch Pattern🔗

 (require freer-lib/try-catch) package: freer-lib

The try-catch pattern provides a mechanism for short-circuiting effectful computations. A computation wrapped with try that returns #f aborts the computation up to the nearest enclosing catch, and the fallback given to try is used as the result of that catch instead.

procedure

(try computation fallback) → free?

  computation : free?
  fallback : free?
Runs computation. If its result is anything other than #f, that result is returned unchanged. If its result is #f, an internal failure effect carrying fallback is performed, which the nearest enclosing catch handles by discarding the rest of its computation and continuing with fallback.

The failure effect is private to this module, so try must be used inside a catch; otherwise the failure effect reaches the handler given to run, which cannot recognize it.

Examples:
> (define computation
    (do-m [x <- (return 10)]
          (if (> x 20)
              (return x)
              (return #f))))
> (run (catch (try computation (return 'fallback-value)))
       (lambda (eff k) (k eff)))

'fallback-value

procedure

(catch computation) → free?

  computation : free?
Handles the failures raised by try inside computation. When a failure occurs, the remainder of computation is skipped and the resulting computation continues with the fallback that was passed to try. All other effects are passed on unchanged, so they are handled by the enclosing handler (or an enclosing catch), and computation resumes with their result as usual.

Examples:
> (define (handler eff k)
    (match eff
      ['get-number (k 2)]))
> (define failing-computation
    (do-m [a <- (perform 'get-number)]
          [b <- (try (return #f) (return 100))]
          (return (+ a b))))
; The fallback replaces the whole caught computation
> (run (catch failing-computation) handler)

100

; Code outside the catch continues with the fallback's result
> (run (do-m [a <- (perform 'get-number)]
             [b <- (catch (try (return #f) (return 100)))]
             (return (+ a b)))
       handler)

102

3.10.1 Usage Pattern🔗

The typical pattern for using try-catch is:

  • Wrap computations that might return #f with try, providing a fallback.

  • Wrap the sequence of computations that should be aborted on failure with catch.

  • If a computation wrapped in try returns #f, the computations after it (up to the catch) are skipped, and the catch produces the result of the fallback.

  • If all computations succeed (return non-#f values), the computation proceeds normally.

Examples:
> (define (check-positive n)
    (if (positive? n)
        (return n)
        (return #f)))
> (define (sum-of-positives x y z)
    (do-m [a <- (try (check-positive x) (return 'not-positive))]
          [b <- (try (check-positive y) (return 'not-positive))]
          [c <- (try (check-positive z) (return 'not-positive))]
          (return (+ a b c))))
> (run (catch (sum-of-positives 5 3 10))
       (lambda (eff k) (k eff)))

18

> (run (catch (sum-of-positives 5 -3 10))
       (lambda (eff k) (k eff)))

'not-positive
